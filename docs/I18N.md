# MỘC HEALTHY — I18N HANDBOOK
## Sổ tay đa ngôn ngữ, quy ước dịch và typography

> File này là nguồn sự thật cho mọi việc liên quan đến ngôn ngữ hiển thị, bản dịch nội dung và font chữ.
> Kiến trúc kỹ thuật chi tiết nằm ở `docs/PLAN.md` mục **31A. Internationalization & Localization**.
> Mọi coding agent phải đọc file này trước khi thêm bất kỳ chuỗi hiển thị, enum, thông báo lỗi hoặc trường text nào.

# 1. Ngôn ngữ hỗ trợ

| Locale | Ngôn ngữ | Vai trò | `html lang` | URL storefront | OG locale |
|---|---|---|---|---|---|
| `vi` | Tiếng Việt | **Mặc định**, nguồn sự thật, fallback cuối | `vi` | `/` (không prefix) | `vi_VN` |
| `en` | English | Khách quốc tế, đối tác | `en` | `/en/...` | `en_US` |
| `zh-CN` | 简体中文 (Trung giản thể) | Khách Trung Quốc đại lục, Singapore, Malaysia | `zh-CN` | `/zh-CN/...` | `zh_CN` |
| `zh-TW` | 繁體中文 (Trung phồn thể) | Khách Đài Loan, Hồng Kông, Ma Cao | `zh-TW` | `/zh-TW/...` | `zh_TW` |

Quy tắc:
- Mã locale dùng **thống nhất** ở URL, cookie `NEXT_LOCALE`, `html lang`, cột `locale` trong DB, query `lang`, header `Accept-Language`. Không dùng `zh-Hans`, `zh-Hant`, `vn`, `cn`, `tw` ở bất kỳ đâu.
- Chuỗi fallback khi thiếu bản dịch: `en → vi`, `zh-CN → zh-TW → vi`, `zh-TW → zh-CN → vi`. Fallback chỉ áp dụng cho **nội dung DB**; file ngôn ngữ UI bắt buộc đủ 100% key (script `i18n:check` chặn).
- Thứ tự resolve locale ở API: query `lang` > header `Accept-Language` > `vi`.
- Thứ tự resolve ở storefront: segment URL > cookie `NEXT_LOCALE` > `Accept-Language` > `vi`. Ở admin: cookie `NEXT_LOCALE` > `users.preferred_locale` > `vi`.

# 2. Hai loại văn bản, hai cơ chế khác nhau

| Loại | Ví dụ | Nơi lưu | Ai viết | Dịch máy? |
|---|---|---|---|---|
| **Chuỗi giao diện (UI strings)** | nhãn nút, menu, tiêu đề cột, thông báo lỗi, trạng thái, placeholder, toast, metadata trang tĩnh | `messages/<locale>/<namespace>.json` trong repo | Coding agent / dev, **viết tay từng ngôn ngữ** trong cùng một prompt | **Không.** Không dùng Google Translate widget, không dịch lúc chạy, không sinh file bằng script dịch tự động |
| **Nội dung kinh doanh (Business content)** | tên, mô tả, SEO của sản phẩm, danh mục, khuyến mãi; bài content AI | Bảng `*_translations` trong DB | Nhân viên nhập trong admin | **Có hỗ trợ:** nút "AI dịch các ngôn ngữ còn lại" tạo **bản nháp**, người dùng xem lại, sửa, rồi bấm Lưu |

# 3. Cấu trúc file ngôn ngữ

```text
packages/i18n/
├── src/
│   ├── locales.ts          # SUPPORTED_LOCALES, DEFAULT_LOCALE, LOCALE_LABELS, OG_LOCALES, FALLBACK_CHAIN
│   ├── formatters.ts       # formatCurrency, formatNumber, formatDate, formatDateTime, formatRelative
│   └── index.ts
├── messages/
│   ├── vi/   common.json  errors.json  enums.json
│   ├── en/   common.json  errors.json  enums.json
│   ├── zh-CN/ common.json errors.json  enums.json
│   └── zh-TW/ common.json errors.json  enums.json
├── check-allowlist.json    # giá trị được phép trùng giữa các locale (tên thương hiệu, SKU, "OK", "Email"...)
└── scripts/check.mjs       # npm run i18n:check

apps/storefront-web/messages/<locale>/
  home.json  product.json  category.json  search.json  cart.json  checkout.json
  tracking.json  promotions.json  layout.json  seo.json

apps/admin-web/messages/<locale>/
  nav.json  dashboard.json  auth.json  products.json  inventory.json  promotions.json
  orders.json  customers.json  marketing.json  content.json  analytics.json
  automation.json  aiStudio.json  social.json  settings.json
```

Quy tắc đặt key:
- Namespace = tên module, key = camelCase, lồng tối đa 3 cấp: `orders.table.columns.total`.
- Enum/status dùng chung giữa 2 app đặt tại `packages/i18n/messages/<locale>/enums.json`, key phản chiếu đúng tên type trong `packages/contracts`: `enums.OrderStatus.CONFIRMED`, `enums.BrandTone.FRESH_ENERGETIC`.
- Thông báo lỗi backend đặt tại `errors.json`, key = `error_code` do API trả về: `errors.PRODUCT_NOT_FOUND`, `errors.VALIDATION_ERROR`. Luôn có `errors.UNKNOWN`.
- Không đặt key theo nội dung tiếng Việt (`"luuThanhCong"`), đặt theo ý nghĩa (`"saveSuccess"`).
- Một key = một câu hoàn chỉnh. **Cấm nối chuỗi** (`t('added') + ' ' + name + ' ' + t('toCart')`). Dùng ICU placeholder: `"addedToCart": "Đã thêm {name} vào giỏ hàng"`.
- Số nhiều dùng ICU plural. `vi`, `zh-CN`, `zh-TW` chỉ có nhánh `other`; `en` bắt buộc có `one` và `other`:
  ```json
  "itemCount": "{count, plural, one {# item} other {# items}}"
  ```
- Ngày, tiền, số **không** nằm trong chuỗi dịch; truyền giá trị đã format qua placeholder.

Kiểm tra tự động (`npm run i18n:check`, chạy trong `npm run lint`) sẽ **fail** khi:
1. Một locale thiếu key hoặc thừa key so với `vi`.
2. Giá trị rỗng.
3. Giá trị ở `en`, `zh-CN`, `zh-TW` trùng y nguyên với `vi` mà không nằm trong `check-allowlist.json`.
4. Giá trị `zh-TW` trùng y nguyên với `zh-CN` (dấu hiệu chỉ copy, chưa dịch).
5. Cú pháp ICU sai.
6. Grep thấy `'vi-VN'`, `toLocaleString(`, `toLocaleDateString(`, `toLocaleTimeString(` trong `apps/*/src` ngoài `packages/i18n`.
7. Grep thấy chuỗi tiếng Việt có dấu trong file `.tsx`/`.ts` ngoài thư mục `messages/`, `seed`, test.

# 4. Định dạng tiền, ngày, số

Chỉ dùng formatter trong `@moc-healthy/i18n`. Cấm `Intl.*` trực tiếp trong component, cấm helper cục bộ.

| Giá trị | vi | en | zh-CN | zh-TW |
|---|---|---|---|---|
| Tiền (luôn VND) | `49.000 ₫` | `₫49,000` | `₫49,000` | `₫49,000` |
| Số | `1.234.567` | `1,234,567` | `1,234,567` | `1,234,567` |
| Ngày | `12/10/2026` | `Oct 12, 2026` | `2026年10月12日` | `2026年10月12日` |
| Ngày giờ | `12/10/2026 15:20` | `Oct 12, 2026, 3:20 PM` | `2026年10月12日 15:20` | `2026年10月12日 下午3:20` |
| Múi giờ | Luôn `Asia/Ho_Chi_Minh` cho mọi locale (cửa hàng ở Việt Nam) | | | |

- Đơn vị tiền tệ **không bao giờ** đổi sang USD/CNY/TWD. Không quy đổi tỷ giá.
- Form nhập liệu (input date, number) dùng giá trị ISO, không phụ thuộc locale.

# 5. Typography & Font

| Locale | Body / UI | Heading storefront | Heading admin | Weight dùng |
|---|---|---|---|---|
| `vi`, `en` | **Inter** (subset `latin`, `vietnamese`) | **Playfair Display** (subset `latin`, `vietnamese`) | Inter 600/700 | 400, 500, 600, 700 |
| `zh-CN` | **Noto Sans SC** | **Noto Sans SC 700** | Noto Sans SC 500/700 | 400, 500, 700 |
| `zh-TW` | **Noto Sans TC** | **Noto Sans TC 700** | Noto Sans TC 500/700 | 400, 500, 700 |

Cách nạp:
- Inter và Playfair Display qua `next/font/google` (self-host, không layout shift), gán CSS variable `--font-inter`, `--font-playfair`.
- Noto Sans SC/TC qua thẻ `<link>` Google Fonts với `display=swap` và `preconnect`, **chỉ render khi locale bắt đầu bằng `zh`** (Google CSS cắt unicode-range nên trình duyệt chỉ tải vài trăm KB; `next/font` sẽ tải toàn bộ ~100 slice lúc build, rất chậm).
- Biến dùng trong Tailwind: `--font-sans`, `--font-display`. Mặc định `--font-sans: var(--font-inter), system-ui, sans-serif`, `--font-display: var(--font-playfair), serif`.
- Override theo locale trong `globals.css`:
  ```css
  html[lang="zh-CN"] { --font-sans: "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif; --font-display: var(--font-sans); }
  html[lang="zh-TW"] { --font-sans: "Noto Sans TC", "PingFang TC", "Microsoft JhengHei", sans-serif; --font-display: var(--font-sans); }
  html[lang^="zh"] body { line-height: 1.7; letter-spacing: 0; }
  ```
- Quy tắc heading ở locale zh: **toàn bộ heading** dùng Noto Sans 700, không trộn Playfair (serif) với Noto (sans) trong cùng một dòng. Chỉ wordmark "Mộc Healthy" trên header/footer giữ Playfair.
- Không dùng `font-style: italic` cho chữ Hán. Không dùng `uppercase` cho chữ Hán. Không `letter-spacing` âm.
- Kích thước chữ tối thiểu: body 14px admin, 15px storefront; chữ Hán ở mobile tối thiểu 15px.
- Scale heading storefront: `display-xl 40/48`, `h1 32/40`, `h2 24/32`, `h3 20/28`, `body 16/24` (px / line-height). Admin: `h1 24/32`, `h2 18/28`, `body 14/20`.

# 6. Quy tắc chất lượng bản dịch

## 6.1 Chung
- Viết như người bản ngữ viết cho khách hàng F&B, không dịch sát từng chữ. Ưu tiên câu ngắn, giọng ấm, tươi, không khoa trương.
- Giữ nguyên tên thương hiệu và tên riêng: `Mộc Healthy`, `Mộc Xu`, `VietQR`, `GrabFood`, `ShopeeFood`, `Zalo`, `TikTok`.
- Độ dài: `en` thường dài hơn `vi` 10–30%, chữ Hán ngắn hơn 30–50%. UI phải chịu được cả hai (không cắt chữ, không tràn nút).
- Placeholder giữ nguyên tên biến `{name}`, `{count}`, `{amount}` ở mọi ngôn ngữ.
- Không để lại chữ tiếng Việt trong bản en/zh (trừ tên riêng). Không để lại chữ Hán giản thể trong bản zh-TW.

## 6.2 Tiếng Anh (`en`)
- Chính tả Mỹ (`color`, `flavor`, `favorite`). Title Case cho tiêu đề trang và nút chính, Sentence case cho mô tả.
- Xưng hô trực tiếp với khách ("Your order", "Add to cart"). Admin dùng mệnh lệnh ngắn ("Save", "Approve", "Publish").

## 6.3 Trung giản thể (`zh-CN`) và Trung phồn thể (`zh-TW`)
- **`zh-TW` KHÔNG phải là bản chuyển mã ký tự của `zh-CN`.** Cấm dùng OpenCC hoặc bảng chuyển giản/phồn để sinh `zh-TW`. Hai thị trường dùng từ vựng khác nhau, phải viết riêng.
- Dấu câu toàn hình: `，。！？：；（）` cho cả hai. `zh-TW` dùng ngoặc kép `「」`, `zh-CN` dùng `“”`.
- Không có khoảng trắng giữa chữ Hán; có một khoảng trắng giữa chữ Hán và chữ Latin/số (`配送 30 分钟`).

# 8. Nội dung kinh doanh trong DB

## 8.1 Mô hình
- Cột gốc trong `products`, `categories`, `promotions` luôn là **tiếng Việt** (nguồn sự thật).
- Bản dịch nằm ở `product_translations`, `category_translations`, `promotion_translations`, mỗi hàng = một `(entity_id, locale)`, chỉ tồn tại cho `en`, `zh-CN`, `zh-TW`. Không có hàng = `MISSING`.
- Mỗi hàng có `status` (`AI_DRAFT` | `REVIEWED`), `is_ai_generated`, `source_hash` (sha256 các trường vi tại thời điểm dịch), `updated_by`, `updated_at`.
- Khi bản vi thay đổi, `source_hash` lệch → admin hiển thị badge **Outdated**, storefront vẫn dùng bản dịch cũ cho đến khi được cập nhật.
- Slug, SKU, giá, hình ảnh, tags kỹ thuật **không dịch**.

## 8.2 Quy trình trong admin (tab "Bản dịch")
```text
1. Nhập/sửa nội dung tiếng Việt như bình thường → Lưu.
2. Mở tab "Bản dịch": 4 cột vi | en | zh-CN | zh-TW, mỗi cột có badge MISSING / AI_DRAFT / REVIEWED / OUTDATED.
3. Bấm "AI dịch các ngôn ngữ còn lại" → API POST .../translations/ai-draft
   → AI trả bản nháp cho các locale đang MISSING hoặc OUTDATED (không ghi DB).
4. Người dùng đọc, sửa trực tiếp trong form.
5. Bấm "Lưu bản dịch" → API PUT .../translations → status = REVIEWED, source_hash cập nhật.
6. Storefront chỉ hiển thị hàng có trong DB (AI_DRAFT chưa lưu không bao giờ lộ ra ngoài).
```
- Quyền: `translations.manage` (Marketing, Admin). Nút AI dịch yêu cầu thêm `ai.use`.
- AI dịch luôn đi qua `AIService` (PII masking, log token, chi phí) với template `content-translation`; output JSON được validate bằng Pydantic, kiểm tra tên thương hiệu và placeholder còn nguyên, từ chối trường rỗng.
- Khi `AI_PROVIDER=mock`, bản nháp có dạng `[en] <nội dung gốc>` để test ổn định.

## 8.3 API
```text
GET    /api/v1/{products|categories|promotions}/{id}/translations
PUT    /api/v1/{products|categories|promotions}/{id}/translations        body: { "en": {...}, "zh-CN": {...}, "zh-TW": {...} }
POST   /api/v1/{products|categories|promotions}/{id}/translations/ai-draft  body: { "target_locales": ["en","zh-TW"], "overwrite": false }
GET    /api/v1/storefront/...?lang=zh-TW   → response có "locale" và từng item có "content_locale" (locale thực sự được dùng sau fallback)
```

# 9. Thông báo lỗi API

- Backend ném `AppError(code, status, message_vi, params)`; exception handler trả:
  ```json
  { "detail": { "code": "PRODUCT_NOT_FOUND", "message": "Không tìm thấy sản phẩm", "params": {} } }
  ```
- Frontend hiển thị `t('errors.' + code, params)`; nếu không có key thì hiển thị `message` (tiếng Việt) và log cảnh báo thiếu key.
- Mọi `code` mới phải được thêm vào `errors.json` của cả 4 locale trong cùng prompt.
- Lỗi validate Pydantic → `VALIDATION_ERROR` kèm `params.fields`.

# 10. SEO đa ngôn ngữ (storefront)

- Mỗi trang có `generateMetadata` theo locale: `title`, `description`, `openGraph.locale`, `alternates.languages` gồm 4 locale + `x-default` = vi.
- Sitemap tách theo locale, robots cho phép tất cả.
- Hình ảnh dùng chung, `alt` dịch theo locale.
- Không tự động chuyển hướng theo IP; chỉ gợi ý bằng banner nhỏ "Switch to English?" khi `Accept-Language` khác locale hiện tại.

# 11. Checklist trước khi đóng một prompt

```text
[ ] Không có chuỗi hiển thị hard-code trong .tsx/.ts (ngoài messages/, seed, test).
[ ] Mọi key mới có mặt ở vi, en, zh-CN, zh-TW và được viết tay theo bản ngữ.
[ ] zh-TW không trùng zh-CN; en/zh không trùng vi (trừ allowlist).
[ ] Tiền/ngày/số đi qua @moc-healthy/i18n formatters.
[ ] Enum/status mới có enums.<Type>.<VALUE> ở 4 locale.
[ ] Error code mới có errors.<CODE> ở 4 locale.
[ ] Trường text DB mới cần dịch đã có bảng *_translations, localize(), seed 4 locale.
```
